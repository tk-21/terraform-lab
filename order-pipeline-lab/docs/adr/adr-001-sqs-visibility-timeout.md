# ADR-001: SQS visibility_timeout_seconds の設定値

## Status
Accepted

## Context

SQS から注文メッセージを受信した後、Step Functions ステートマシンを起動して処理を行う。
このフロー全体（在庫確認 → 決済処理 → 通知送信）が完了するまで、他のコンシューマーが同じメッセージを受信しないようにする必要がある。

SQS の `visibility_timeout_seconds` は、メッセージを受信してから処理完了（削除）までの猶予時間を制御する。
この値が実際の処理時間より短いと、処理中にメッセージが「再可視化」され、別のワーカーに二重配信される。

今回の構成では決済処理が ECS Fargate コンテナで動作するため、コールドスタート込みで最大 5分程度かかる可能性がある。

## Decision

`visibility_timeout_seconds = 300`（5分）に設定する。

AWS のドキュメントでは、Lambda のタイムアウト値の 6倍を推奨しているが、
本プロジェクトでは Step Functions を介した非同期処理のため、エンドツーエンドの処理時間を基準にした。

## Consequences

**良い面:**
- 処理中の二重配信を防止できる
- ECS Fargate のコールドスタートを考慮した余裕のある設定

**悪い面・トレードオフ:**
- 処理が途中でクラッシュした場合、次のリトライまで最大 5分待つことになる
- `maxReceiveCount = 3` と組み合わせると、最悪 15分間メッセージが宙ぶらりんになる可能性がある
- 本番環境では処理時間の実測値を取り、適切な値に調整が必要
