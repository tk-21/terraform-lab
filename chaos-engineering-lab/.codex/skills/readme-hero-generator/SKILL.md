このスキルは、プロジェクト内容を短時間で伝える README 向けヒーロー画像を安定して作るためのワークフローを定義する。

## 使う場面
- ユーザーが「README 用の画像を作って」「README に入れて」と依頼したとき
- 既存 README の冒頭訴求を強化したいとき
- 他プロジェクトへ同じ進め方を横展開したいとき

## 成果物
- `docs/readme-hero.png`
- 必要に応じて `docs/readme-hero.svg`
- `README.md` への埋め込み

## 標準フロー
1. `README.md` を読む
2. 必要に応じて `ARCHITECTURE.md`、`docs/`、`runbooks/`、主要コードを読み、図に含める情報を絞る
3. `docs/readme-hero-spec.md` があれば優先して読む
4. README 埋め込み向けの横長構成で画像生成プロンプトを組み立てる
5. 生成画像のうち、README に最も適したアスペクト比と視認性のものを採用する
6. 採用画像を `docs/readme-hero.png` に配置する
7. `README.md` のタイトル・概要・バッジ直下へ画像を埋め込む
8. 保存先、差し込み位置、今後の差し替え方針をユーザーへ共有する

## プロンプト方針
- 画像は横長で、GitHub README 埋め込みに適した比率にする
- 長文説明ではなく、短い見出し・フロー・チップ・アイコンを使う
- 「何を作るプロジェクトか」「どう動くか」「何が学べるか」が一目で伝わるようにする
- スクリーンショット依存にしない
- 既存プロジェクトのトーンがある場合はそれに寄せる

## 推奨構成
- 左: タイトル、1 行要約、短いバッジ
- 中央: アーキテクチャまたは処理フロー
- 下: 3〜5 ステップの短い流れ
- 右または下: 学習ポイント、強み、安全設計などの短い訴求

## 埋め込みの標準形
通常は Markdown を使う。

```md
![readme hero](docs/readme-hero.png)
```

表示サイズの調整が必要な場合のみ HTML を使う。

```html
<img src="docs/readme-hero.png" alt="readme hero" width="100%">
```

## 注意点
- README 内に既存画像がある場合は、役割重複を避ける
- 情報を詰め込みすぎない
- 文字が小さくなりすぎる場合は要素数を減らす
- 図の正確性が重要なときは README だけでなく設計ドキュメントも確認する
