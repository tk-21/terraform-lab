# Step 2 — EC2 プロンプト集

## 学習目標
- Security Group のインバウンド/アウトバウンドルールを設計する
- `data` ソースで最新 AMI を動的取得する
- UserData でインスタンス起動時の初期設定を自動化する
- Elastic IP でパブリック IP を固定化する

---

## 🟢 Step 1: 初期構築・動作確認

```
01_vpc の出力値を取得して 02_ec2 ディレクトリで terraform apply を実行してください。

以下のコマンドで値を取得してから apply してください:
  VPC_ID=$(cd ../01_vpc && terraform output -raw vpc_id)
  SUBNET_ID=$(cd ../01_vpc && terraform output -json public_subnet_ids | jq -r '.[0]')

  terraform apply \
    -var="vpc_id=$VPC_ID" \
    -var="public_subnet_id=$SUBNET_ID"
```

```
apply 完了後、terraform output の web_url にブラウザでアクセスし、
Apache の画面（インスタンス情報）が表示されることを確認してください。
表示された情報（instance_id / AZ など）を読み解いて説明してください。
```

## 🟡 Step 3: コードを改造して学ぶ

```
02_ec2/variables.tf の ssh_allowed_cidr を自分の現在の IP アドレスに変更して
terraform apply で Security Group を更新してください。
自分の IP は https://checkip.amazonaws.com で確認できます。
変更前後で plan の差分を確認し、変更内容を説明してください。
```

```
UserData を改造して、以下の情報も HTML に追加表示してください:
- インスタンスの private IP アドレス
- 使用中のメモリ量（free コマンド）
変更後に terraform apply -replace="aws_instance.web" でインスタンスを再作成して確認してください。
```

```
02_ec2/main.tf に以下のリソースを追加してください:
- S3 バケット（バケット名: handson-<ランダムサフィックス>）
- EC2 から S3 にアクセスできる IAM Role + Instance Profile
- EC2 に Instance Profile をアタッチ

理由: 本番ではアクセスキーを EC2 に持たせず IAM Role で権限を付与するのがベストプラクティス
```
