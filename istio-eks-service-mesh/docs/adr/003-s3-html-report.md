# ADR 003: 可視化ダッシュボードとして S3 HTML レポートを採用する

## Status

Accepted

## Context

Istio サービスメッシュの観測レポートをチームや面接官に共有する手段が必要だった。
候補として以下の3つを検討した:

| 選択肢 | コスト | アクセス方法 | リアルタイム性 |
|---|---|---|---|
| Kiali | 無料（EKS上で動作） | kubectl port-forward 必須 | リアルタイム |
| Grafana | 無料（EKS上で動作） | kubectl port-forward 必須 | リアルタイム |
| S3 HTML レポート | ~$0.01/月 | 署名付きURL | バッチ生成 |

## Decision

S3 に静的 HTML レポートを生成・配置し、署名付きURL（Pre-Signed URL）で共有する方式を採用する。

## Reasons

1. **コストゼロに近い**: Kiali/Grafana は EKS Pod として常時稼働させる必要があり、コントロールプレーン削除後はアクセス不能になる。S3 は ~$0.01/月で永続する。
2. **ポートフォワード不要**: `kubectl port-forward` なしでブラウザから直接アクセスできるため、面接・レビュー時のデモが容易。
3. **安全な共有**: 署名付きURL は有効期限付きで発行でき、IAM 不要で特定の相手だけに共有できる。
4. **ポートフォリオ適合**: 実際のインフラを削除した後もレポートが残るため、ハンズオン成果の証跡として機能する。

## Consequences

- **リアルタイム性の欠如**: Kiali/Grafana と違い、メトリクスはバッチ生成（`scripts/generate_report.py` 実行時点のスナップショット）。
- **手動トリガー**: レポート更新には `generate_report.py` の再実行が必要。CI/CD パイプラインで定期実行することで緩和できる。
- **Istio メトリクス収集**: Prometheus が起動していない場合、`kubectl top` ベースの簡易メトリクスにフォールバックする。
